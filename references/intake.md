# Shared intake

Read existing documents and session facts first. Ask only unanswered questions
that materially affect the requested work. Accept concise user descriptions as
user-reported facts; do not relabel them as independently verified evidence.

| Area | Establish | Useful source |
|---|---|---|
| Request | New program, adaptation, or targeted revision; audience; output format | User instructions |
| Company | Legal entity, activities, products, software, services, customers, locations | Company description and contracts |
| Applicability | Known jurisdiction and classification determinations; CUI and classified scope separately | Determination records, contract clauses, markings with provenance |
| Access | Employees, contractors, visitors, owners, suppliers, administrators, locations, eligibility determinations | Role and access matrix; approved screening process |
| Information flows | Creation, receipt, storage, processing, transmission, backup, support, disposal | Diagrams, SSP, service descriptions |
| International activity | Foreign recipients, affiliates, travel, remote support, demonstrations, exports and retransfers | Business process descriptions and transaction records |
| Authorizations | Relevant registrations, licenses, agreements, exceptions/exemptions relied upon, provisos, expiration and scope | Authorization records and responsible official confirmation |
| Governance | Export official, legal support, system owners, release approvers, training and audit owners | Approved organization chart and policies |
| Baseline | Document identifiers, revisions, approval status, canonical SSP, NIST revision, known conflicts | Document register and supplied files |
| Evidence | Governance evidence versus operational records; confirmed versus proposed safeguards | Policies, configurations, logs, completed records |

Capture decisions as: topic; supplied fact and source; verification status;
remaining question; drafting impact; responsible person; resolution status.
Use named roles when individuals are unknown. Leave deadlines unresolved unless
provided or explicitly proposed. Do not request unnecessary personal records or
controlled technical content; request descriptions or redacted excerpts when sufficient.

Select an intake route without repeated confirmation when context is clear.
For partial information, draft unaffected sections and identify specific placeholders.
For a SaaS company, examine both storage and plaintext analysis/testing, including
customer uploads, subprocessors, support personnel, logs, backups, and output data.
Do not assume that a storage safeguard establishes conditions for processing.
